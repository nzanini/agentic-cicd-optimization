# B2 — agentic optimizer (Phase 2.4 / 2.6)

**Phase:** 2.4 implementation; **2.6** local live path; **2.7** proposal validity; **2.10** stronger local substitution  
**Status:** implemented; **rejected as the production optimizer** (D-050). Keep as experiment and learning.  
**Date:** 2026-08-29  
**Does not claim:** a simulated-cost win vs B1 on S01–S14 or S16–S18 (E-010/E-011 Q1 parity)

B2 is an experimental **job-selection** wrapper, not a different workload. Catalog Ranker stays a frozen-weight batch ranker. B2 runs **B1 first**. An optional read-only agent may propose a tighter plan. A **deterministic verifier** is the only authority that can narrow a B1 RUN to SKIP. Execution uses the existing B0 job bodies.

**Judges do not need B2, Ollama, an API key, or Cursor** to reproduce the headline B0→B1 result. This file documents an experiment that did not beat B1.

Related: [AGENT_DESIGN.md](AGENT_DESIGN.md), [B1.md](B1.md), [OPTIMIZATION_CONTRACT.md](OPTIMIZATION_CONTRACT.md), [AGENT_PROVIDER_RESEARCH.md](AGENT_PROVIDER_RESEARCH.md), D-035–D-037, D-041–D-045, E-004, E-006, E-008.

## 1. What was implemented

```text
B1 plan
  → invocation policy (machine-readable)
  → optional agent (read-only tools → b2_proposal JSON)
  → deterministic verifier
  → execute verified plan
```

Package: `src/agentic_cicd/b2/`

| Module | Role |
| --- | --- |
| `policy.py` | Invoke / do-not-invoke |
| `settings.py` | Env-only credentials and knobs |
| `provider.py` | One OpenAI-compatible HTTP client + `FakeProvider` |
| `tools.py` | Eight read-only tools, path-jailed |
| `context.py` | Bounded context (no scenario id, no secrets) |
| `schema.py` | Strict `b2_proposal` validation |
| `agent.py` | Tool loop; never executes jobs |
| `verifier.py` | Independent of the LLM |
| `execute.py` / `runner.py` | Final plan through existing jobs |

CLI: `python -m agentic_cicd b2 ...`  
Benchmark: `--system agentic` (B2) or `--system ladder` (B0+B1+B2). `--system compare` remains B0 vs B1. Agent-value rows: `--scenarios benchmark/agent_value_scenarios.json`.

## 2. Model / provider

**Primary path:** one OpenAI-compatible Chat Completions client via stdlib `urllib`. No extra pip dependency. No second provider class.

| Item | Value |
| --- | --- |
| Provider interface | `OpenAICompatProvider` (`openai_compatible`) |
| Default host | `https://api.openai.com/v1` if `B2_BASE_URL` unset (hosted path stays **offline** without a key) |
| Default live model | **`qwen2.5:3b`** when `B2_BASE_URL` is local (D-041). E-011 tried `qwen3:4b-instruct` via env only; default unchanged. Hosted default `gpt-4o-mini` is unused. |
| Credential | Local: none. Hosted: `B2_API_KEY` only. Never committed. Not `OPENAI_API_KEY`. |
| Expected list price | Local **$0**. Hosted estimate unused (~$0.15 / $0.60 per 1M tokens). |
| Expected latency | ~3–5 min/invocation on 8 GB CPU (E-006); 0 when not invoked |
| Why this path | One HTTP adapter; Ollama is replaceable via env; no Cursor/vendor SDK |
| Offline / test | No local runtime and no key, `B2_DISABLED=1`, probe fail, timeout, HTTP error, or malformed JSON → B1. Tests inject `FakeProvider`. |

E-004 ran **without** `B2_BASE_URL` / key. E-006 ran **with** local Ollama. Both: model API cost = $0. E-006 latency is real local compute, not monetized.

## 3. Invocation policy

B1 always runs. The agent is invoked only when **all** of the following hold:

- flow is legal;
- B1 has conservative residue (`unknown` / `dependencies` / `orchestrator` / `changed_paths is None`);
- residue is inspectable in the workspace or repo;
- expected max save ≥ `B2_MIN_SAVE` (default 5);
- `B2_DISABLED` is not set;
- a local runtime is available **or** a hosted `B2_API_KEY` is present.

Otherwise the reason is recorded (`b1_sufficient`, `illegal_flow`, `offline`, `disabled`, `not_inspectable`, `not_worth_it`) and B1 executes.

On S01–S14 offline: S01–S06 and S08–S13 are `b1_sufficient`; S11 is `illegal_flow`; S07 and S14 are `offline`.  
On S01–S14 with local Ollama (E-006): S07 and S14 invoke (`conservative_residue`); both fell back `malformed`.

## 4. Verifier (stricter than Phase 2.3 option 2)

The verifier does not call a model and does not “trust the model.”

- Extra RUN is allowed except illegal publish/promote.
- B1 SKIP stays SKIP.
- Narrowing SKIP requires **positive** mechanical evidence:
  1. `discovered_edges` maps every conservative path to a known component with a checkable import/read needle, then re-plan as B1 on the localized paths; or
  2. cache identity (`has_valid` and artifact not invalidated).
- **Inert unknown (no search hits) is not accepted.** Absence of hits is not proof. Accepting it would false-skip S14 (CD-004 / D-036).
- Never skip `branch_guard`.
- Producer/consumer: skip A only if valid X exists and X is not invalidated, or no running consumer needs X.
- `uncertain: true` or `confidence < 0.7` → keep B1 for contested skips.
- Malformed / missing proposal → entire fallback to B1.

## 5. Observability

Each B2 run writes `b2_record.json` (no secrets):

`run_id`, `started_at`, `agent_invoked`, `invocation_reason`, `provider`, `model`, `base_url`, `local`, `latency_ms`, token/cost estimates, `api_cost_usd`, `proposal`, `agent_error`, verifier result, `novel_accept`, `novel_reject`, final plan, executed jobs, `fallback_reason`. No secrets.

`novel_accept`: B1 RUN ∧ agent SKIP ∧ verifier accepts.  
`novel_reject`: agent extra SKIP ∧ verifier rejects.

## 8. Final product decision

B2 is **not** the submitted optimizer. It is a fail-closed wrapper that can invoke a local model and must fall back to B1. Under $0, B1 is preferred (D-050). Cursor is not this runtime.
