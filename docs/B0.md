# B0 — executable CI/CD baseline

**Status:** implemented (Phase 1.5; promote semantics corrected in Phase 1.6.1). This is the **unoptimized baseline** in the final comparison. It does not skip jobs and is not an agent. Phase 2.2 added B1 beside B0 and **did not change B0 scheduling**. `JobRecord.skip_reason` exists for B1 observability and stays unused in B0.

Measured S01–S14 cost after the promote correction is **375** (E-002). B1 is **220** on the same suite (E-003).

B0 is a local, deterministic workflow runner. It is not GitHub Actions. The S01–S14 suite **measures** B0 against ground truth; that is not a comparison to an optimizer.

Score jobs now merge `configs/scoring_weights.json` when present. That overlay exists so S12 is a real hidden dependency, not a documentation-only claim.

## Job graph

```text
branch_guard → validate → test
                         ↘
                           ingest → prepare → score → evaluate → package → publish or promote
```

`publish` waits for **`package` and `test`**. Rebuild `promote` does the same, plus `branch_guard`, so a failed required job cannot write production. Reuse `promote` is scheduled with `branch_guard` only; `package` and `test` are not run.

| Flow | Jobs executed on success |
| --- | --- |
| `feature` / `custom` / `feature/*` / `custom/*` → `development` | branch_guard, validate, test, ingest, prepare, score, evaluate, package, publish |
| `development` → `main`, `promote_mode=reuse` | `branch_guard`, `promote`. Reuses the development artifact id. No rebuild. |
| `development` → `main`, `promote_mode=rebuild` (default) | same through package, then **promote** (not publish). Promotes the **new** artifact even if its id differs from the development pointer |
| anything else (including feature → main) | `branch_guard` only, **fails** |

`promote_mode` is an **explicit caller input**. The benchmark sets `reuse` when a development→main scenario has an empty `apply` (S09) and `rebuild` when `apply` is non-empty (S10). That is scenario-contract information, not file-diff change detection, path filters, or an optimizer.

Phase 1.6 found that B0 rebuilt on every promote and then **rejected** a new artifact id. That made S09 pass (same id after a wasted rebuild) and S10 fail. That was a **baseline correctness defect**: the Phase 1.3 contract already required dirty promote to succeed with a new validated artifact. Phase 1.6.1 corrected B0 to match that contract. S10 ground truth was not weakened.

## Execution model

`run_b0` schedules the legal job list, topologically sorts it (documented `order`, then name), and runs jobs **sequentially**.

- Success: `status=executed`, `simulated_cost` = design weight from Phase 1.3.
- Failure: `status=failed`; dependents are `blocked` (cost 0) and do not run.
- Parallel-in-the-graph jobs (test vs ingest) still run one after another in B0. That is a simulation choice, not optimization.

Wall-clock milliseconds and simulated cost units are recorded **separately**. Simulated cost is a counter only; B0 does not `sleep`.

## Branch rules

Allowed promotions are hard-coded: feature/custom → development, and development → main. No git ancestry walk.

## Artifacts

Workload jobs write under `<output>/workload/` using the Phase 1.4 ranker. `publish` writes `<registry>/development.json`. `promote` writes `<registry>/production.json` only after a development pointer exists. Clean reuse copies that pointer’s artifact id. Dirty rebuild promotes the newly packaged id and updates the production pointer to it. A failed required job blocks `promote`; production is not rewritten.

## Command

```bash
python -m agentic_cicd b0 --source feature --target development --fixtures fixtures --output outputs/b0 --registry outputs/registry
python -m agentic_cicd b0 --source development --target main --fixtures fixtures --output outputs/b0-prod --registry outputs/registry
python -m agentic_cicd b0 --source development --target main --promote-mode reuse --fixtures fixtures --output outputs/b0-prod --registry outputs/registry
```

`--promote-mode` defaults to `rebuild`. Pass `reuse` only when the caller already knows the development artifact is still valid.
