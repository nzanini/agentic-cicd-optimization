## Philosophy

`required_jobs` is **ground truth**: the minimum jobs needed for correctness after that change.

- Extra jobs are **unnecessary**, not a safety failure.
- A missing required job is a **false skip** and fails correctness.
- Ground truth was written from the Phase 1.3 contract, not generated by B0 or an optimizer.

These rows measure **CI/CD job selection** around the Catalog Ranker batch workload. They are not ML-training experiments. The model is frozen; a scenario either does or does not invalidate batch intermediates (raw data, prepared features, predictions, metrics, bundle).

Three different things:

| Kind | Where |
| --- | --- |
| Benchmark definition | `benchmark/scenarios.json` (in git) |
| B0 baseline measurement | `outputs/benchmark/benchmark_results.json` (generated, not source) |
| B1 / comparison measurement | `outputs/benchmark-e003/` (generated, not source) |

## Command

These commands run **locally**. They do not use GitHub Actions, create Git branches, or open pull requests. Simulated `feature` / `development` / `main` values inside scenarios are flow labels, not repository branches to check out.

```bash
# B0 baseline
python -m agentic_cicd benchmark --output outputs/benchmark
# B1 optimized solution (also re-runs B0 for the comparison file)
python -m agentic_cicd benchmark --system compare --output outputs/benchmark-compare
# optional B2 experiment — offline equals B1; not required for the headline result
python -m agentic_cicd benchmark --system agentic --output outputs/benchmark-b2
# optional B2 experiment — B0 + B1 + B2 ladder
python -m agentic_cicd benchmark --system ladder --output outputs/benchmark-e004
# optional B2 experiment — S16–S18 live/offline agent-value rows (Ollama or key only if you want a live model)
python -m agentic_cicd benchmark --system agentic --scenarios benchmark/agent_value_scenarios.json --output outputs/benchmark-e010-live
```

`--system baseline` (default): **B0 baseline** only.  
`--system optimized`: **B1 optimized solution** only.  
`--system compare`: B0 and B1, plus `comparison.json`.  
`--system agentic`: **optional B2 experiment** only.  
`--system ladder`: B0, B1, and optional B2.

`--scenarios PATH` selects the JSON file. Default is `benchmark/scenarios.json` (S01–S14).

B0 still does not choose jobs. For development→main it maps empty `apply` → `reuse` and non-empty `apply` → `rebuild`.

B1 receives `files_changed ∪ apply-touched paths`. It never receives a scenario id. A last-known-good cache is warmed from pre-apply fixtures. A result is an optimization win only if `safety_gate.optimization_win_eligible` is true (false skips 0, 14/14 correctness, no illegal promotion accepted).

## What S01–S14 represent

Each row is a **repository change class** plus a simulated promotion flow. B0 does not inspect that class: on feature→development it always runs the nine legal jobs (cost 31). On development→main it runs a full rebuild unless the harness passes `promote_mode=reuse` (S09). B1 can skip a job only when the change cannot invalidate that job’s output, or a cached intermediate with matching input identity can be hydrated for downstream consumers.

| ID | Kind of change | What it conceptually affects | Why B0 still over-runs | What B1 can safely skip |
| --- | --- | --- | --- | --- |
| S01 | Docs / markdown only | Nothing in the batch graph | Full feature→dev graph anyway | Everything except `branch_guard` |
| S02 | Tests only | Code trust (`test`), not the bundle | Same | Workload jobs + `publish` (no new artifact) |
| S03 | Scoring / application code | Predictions → metrics → bundle | Same | `ingest` and `prepare` (reuse raw + prepared) |
| S04 | Catalog fixture | Raw data → prepared → scores → bundle | Same | `test` (data change, not a code-trust event) |
| S05 | Prepare code | Prepared features → scores → bundle | Same | `ingest` (reuse raw catalog) |
| S06 | Frozen model file | Effective model → scores → bundle | Same | `ingest`, `prepare`, `test` |
| S07 | Dependencies (`pyproject` / lock) | Unknown; may touch every stage | Same | Nothing; fail closed to the full graph |
| S08 | Pipeline metadata only | Validation report; ranker does not read it | Same | Workload jobs + `publish` |
| S09 | Clean promote (dev→main) | Production pointer only; same artifact id | Harness sets `reuse`; B0 runs `branch_guard` + `promote` | Same required set (already minimal) |
| S10 | Dirty promote (score-like change after validation) | Predictions → bundle; new artifact id | Harness sets `rebuild`; B0 runs the full rebuild graph | `ingest` and `prepare` if those identities still match |
| S11 | Illegal feature→main | Policy only | Both run `branch_guard` and **fail**; no publish/promote | Same |
| S12 | Score weights under `configs/` | Effective model → scores → bundle (looks like S08) | Full graph | `ingest`, `prepare`, `test` — **must not** skip `score` |
| S13 | Evaluate / metric code only | Metrics → bundle; predictions stay valid | Same | `ingest`, `prepare`, `score` (reuse predictions) |
| S14 | Unknown / unmapped path | Unknown impact | Same | Nothing; fail closed to the full graph |

Worked examples of the producer/consumer rule: S03 still **needs** a prepared catalog even though `prepare` is not required to *re-run*. S13 still **needs** `predictions.json` even though `score` is skipped. B1 hydrates those objects from cache. Missing or stale cache → run the producer.

Formal required-job table: [PROBLEM_FRAMING.md](PROBLEM_FRAMING.md) §7. Reuse rule: [OPTIMIZATION_CONTRACT.md](OPTIMIZATION_CONTRACT.md) §2.

## Adversarial cases

- **S12:** `configs/scoring_weights.json` changes scores. Treating `configs/**` like S08 (validate only) would false-skip `score`.
- **S10:** a promote that is not clean; score must run and the new artifact must be promoted.

## B0 promote correction (Phase 1.6.1)

E-001 recorded S10 as a B0 miss: rebuild produced a new id, then promote rejected it. That contradicted the Phase 1.3 / S10 contract. Phase 1.6.1 corrected B0. Ground truth in `benchmark/scenarios.json` is unchanged.

- **S09** (`promote_mode=reuse`): same development artifact id; only `branch_guard` + `promote`.
- **S10** (`promote_mode=rebuild`): required rebuild jobs run; the new artifact is validated and promoted; production points at the new id.

E-001 is historical. The corrected B0 baseline is **E-002**. **E-003** is B0 vs B1 on the same ground truth. **E-004** is offline B2 (= B1, 220). **E-006** is live local B2 (= B1, 220; 2 malformed invocations). **E-008** is off-suite proposal validity (valid copy-B1, no `T` win). **E-010** is the official S16–S18 evaluation (B1 93; live 3B B2 93; Q1 parity; Q2 no). **E-011** is the same rows with `qwen3:4b-instruct` (B1 93; live B2 93; Q1 parity; Q2 no). None of these is an agent-over-B1 claim.

Dual representations (`files_changed` vs `apply`) remain documented, not edited. B1 consumes their union.

## Reproducibility

Same scenarios, same fixtures, same B0 graph → same correctness flags, same executed job lists, same artifact ids. Wall-clock may change.
