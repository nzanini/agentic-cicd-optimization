# B1 — deterministic CI/CD optimizer

**Status:** implemented (Phase 2.2). This is the **selected final optimizer** presented for the hackathon. It is not an agent and does not call an LLM. B2 exists beside it as a measured experiment that did not beat these numbers.

B1 selects jobs with explicit, inspectable rules:

```text
changed paths → components → invalidated artifacts → required jobs
                 ↘ cache identity check for producer/consumer reuse
```

B0 is unchanged. S01–S14 ground truth is unchanged. Scenario IDs never appear in `src/agentic_cicd/b1/`.

## Architecture

| Module | Role |
| --- | --- |
| `b1/classify.py` | Path → component. Unknown paths fail closed. `configs/scoring_weights.json` is a **score input**, not pipeline metadata. |
| `b1/impact.py` | Component → invalidated artifacts; producer/consumer table |
| `b1/cache.py` | Last-known-good intermediates; reuse only when input SHA-256 matches |
| `b1/planner.py` | Builds the RUN set and a machine-readable reason for every job |
| `b1/runner.py` | Hydrates verified cache into the workload dir, then executes B0 job bodies |

B1 reuses B0 job implementations (`run_job`). It does not change B0 scheduling.

## Decision model

Each legal job is `RUN` or `SKIP` with `reason_code` + `reason` written to `decisions.json`.

Typical `reason_code` values: `always_required`, `artifact_invalidated`, `producer_required_for_consumer`, `cache_miss`, `cache_hit`, `inputs_unchanged`, `clean_promote_reuse`, `conservative_unknown_or_ambiguous`, `illegal_flow`, `not_on_flow`.

Skip is allowed only when the planner can name a checkable reason. `changed_paths is None` (unknown change set) is conservative: run every legal job.

## Cache / artifact reuse

A file existing in the cache directory is **not** a hit. `has_valid` compares stored input hashes to the current fixtures (catalog, personas, model, overlay). Missing `meta.json`, missing payload, or hash mismatch → cache miss → run the producer.

The benchmark warms a last-known-good cache from the workspace **before** `apply` (previous-build state). That warm-up is not charged as scenario simulated cost. If the cache is absent or stale, B1 runs upstream jobs (safe, possibly unnecessary).

B1 does not invent empty artifacts.

## Promotion

B1 **infers** clean vs dirty. It does not take `promote_mode` as an optimization input.

- Empty / non-bundle change + development pointer exists → `reuse` (`branch_guard`, `promote`).
- Bundle-invalidating or conservative change → `rebuild` of invalidated jobs + `promote`.
- Illegal feature/custom → main → `branch_guard` fails; no publish/promote.

## Safety

UNKNOWN / dependencies / orchestrator / unclassified path → run the full legal graph.

A suite result is an optimization win only if false skips = 0, correctness is 14/14, and no illegal promotion is accepted. The harness records `safety_gate.optimization_win_eligible`.

## Command

```bash
python -m agentic_cicd b1 --source feature --target development --changed README.md --cache outputs/cache --warm-cache
python -m agentic_cicd benchmark --system compare --output outputs/benchmark-compare
```

`--changed` omitted means the change set is unknown (fail closed). `--changed` with no paths is a known-empty change.

## Measured result (E-003)

See [EXPERIMENT_LOG.md](EXPERIMENT_LOG.md). Suite simulated cost **220** vs B0 **375**, false skips **0**, correctness **14/14**. Not an agent result.

## Limitations

- No git ancestry walk; the caller must supply the change list.
- Cache is local fixture/hash state, not a production artifact store.
- Unmapped paths (e.g. `ranker/io_util.py`) fail closed to the full graph.
- Dirty promote still does not rewrite `development.json` (same as B0).
- Hidden dependencies that are **not** in the component map would be missed unless they look unknown (then we over-run).
